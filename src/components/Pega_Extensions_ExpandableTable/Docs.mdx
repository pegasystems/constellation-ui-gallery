# Overview

The **Expandable Table** renders an embedded data list with an expandable detail panel for each row. Choose a **Variant** to present the same data as a classic table, an accordion list, or category tabs.

Key characteristics:

- **Variants** — `table` (default expandable grid), `list` (accordion rows), or `tabs` (Cosmos Tabs grouping rows by a `Category` column).
- **Read-only cells** — column values are rendered in display-only mode; no inline editing (except boolean select-all checkboxes).
- **Row-level expand/collapse** — a chevron control toggles a detail panel for that row.
- **Configurable detail view** — the view rendered on expand is specified in authoring via the **Detail view name** property; the component delegates to the Constellation `createComponent` API so the view is fully interactive and theme-aware.
- **ID + URL merge** — when a column labeled `ID` is immediately followed by a `URL` field, the two columns are merged into one: the cell shows a link with the ID as the label and the URL as the href.
- **Boolean select-all** — boolean / `Checkbox` columns render as a narrow first data column (no visible label). Checking or unchecking updates that row and every nested boolean field under the row.
- **Sticky first column** — in the table variant, the expand button column stays visible during horizontal scroll.
- **Theme-aware styling** — borders, surfaces, and active tab colors use Cosmos theme tokens (no hardcoded palette values).
- **Lazy component loading** — cell renderers are loaded on demand through the Constellation component registry before the table is displayed.

# Configuration

## Step 1 – Create the table view

In App Studio or Dev Studio, create a new view and select **Expandable Table** as the layout template.

In the **Region A (Columns)** content picker, drill down into your embedded data page-list property and select the fields you want to display as table columns.

## Step 2 – Choose a variant

Set **Variant** to one of:

| Variant   | Behavior                                                                                                                                                                                        |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Table** | Classic expandable data table (default).                                                                                                                                                        |
| **List**  | Accordion list; each row is an expandable item. Prefer a `Title` / `Name` column for the header and an optional `Help` column for AdditionalInfo.                                               |
| **Tabs**  | Tabs. With a `Category` column, categories become tabs and matching rows render as expandable list items. Without `Category`, each row becomes its own tab and the panel shows the detail view. |

## Step 3 – Configure the detail view

In the **Detail view name** property, enter the name of the Pega view that should render when a row is expanded (for example, `ComputerDetails`). This view will be rendered in the context of the individual embedded object at the row's index.

The detail view receives the embedded object as its data context via `pageReference`, so field references inside that view resolve against the selected embedded record automatically.

## How expand works at runtime

When the user expands a row, the component calls `PCore.createPConnect` with:

- `meta.type = 'View'` and `meta.config.name` set to **detailViewName**
- `options.pageReference` set to `caseInfo.content.<embedDataRef>[rowIndex]`

This instructs the Constellation runtime to instantiate the configured view for the embedded object at that row.

## Nested expandable tables

When an Expandable Table is placed inside another table's detail view, the component resolves paths relative to the current view context (`getPageReference()`), not always from `caseInfo.content`. This allows a parent row's detail view to host a child Expandable Table bound to an embedded page list on that row (for example, line items on an order).

For nested authoring:

1. Configure the **parent** table against the top-level page list (for example, `.Orders[]`).
2. Set the parent's **Detail view name** to a view that contains a **child** Expandable Table.
3. In the child table, pick columns from the embedded list on the parent row (for example, `.LineItems[]`).

The child table automatically inherits the parent row's `pageReference` and binds its rows to `caseInfo.content.Orders[n].LineItems[m]`.

## ID + URL linked column

When **Region A (Columns)** includes a field whose label is exactly `ID`, and the **next** column is a `URL` field type, the Expandable Table merges those two columns into one.

| Authoring columns          | Displayed column                                     |
| -------------------------- | ---------------------------------------------------- |
| `ID` then `URL` (adjacent) | Single **ID** column; each cell is a link            |
| Cell content               | Link **label** = ID value; link **href** = URL value |

### Authoring steps

1. Add the identifier field to **Region A** and set its label to `ID` (exact match).
2. Immediately after it, add a property whose type / component is `URL`.
3. Optionally add other columns before or after the pair; only consecutive `ID` + `URL` pairs are merged.

If the columns are not adjacent, or the label is not exactly `ID`, both columns render separately as usual.

## Boolean columns and nested select-all

When you include a **boolean** property (for example `IsSelected`) in **Region A (Columns)**, the Expandable Table renders it as an interactive checkbox instead of display-only text.

Checking or unchecking that checkbox:

1. Updates the boolean on the **current row**.
2. Walks **nested pages and page lists** under that row and sets every boolean field to the same value.

This is similar to [Checkbox Row](?path=/docs/fields-checkbox-row--docs), but children are nested under the row (for example `Documents[0].Files[n].IsSelected`) rather than sibling fields on the same page.

### Authoring steps

1. On the **parent** Expandable Table, add a boolean field such as `.IsSelected` to **Region A (Columns)**. Boolean columns are shown first (after the expand control), in a narrow column with no visible header or checkbox caption.
2. Set **Detail view name** to a view that contains a **child** Expandable Table (or other controls bound to nested data).
3. On the **child** Expandable Table, also include the nested boolean field (for example `.Files[].IsSelected`) if you want those checkboxes visible and kept in sync, and set the child's **Detail view name** so nested rows can expand their own detail view.
4. Use the same property name on parent and child when you want a clear select-all relationship (commonly `IsSelected`).

### Runtime behavior

- Parent checkbox checked → parent `IsSelected = true` and every nested boolean under that row (for example all `Files[].IsSelected`) becomes `true`.
- Parent checkbox unchecked → the same nested booleans become `false`.
- Nested tables subscribe to the Redux store so their checkbox UI refreshes when a parent select-all updates store values.

### Try it

Expand a document, then toggle its **Selected** checkbox. The nested **Files** checkboxes update together.
