# Speech to Text Component

## Overview

The **Speech to Text** component leverages the Web Speech API to capture audio input from users and convert it to text. It's designed for hands-free data entry, accessibility enhancements, and improving user experience in mobile and voice-enabled applications.

### Key Features

- 🎤 **Real-time Speech Recognition**: Captures voice input and converts to text in real-time
- 🌍 **Multi-language Support**: Supports 50+ languages (configurable via `language` prop)
- ✏️ **Editable Text Output**: Users can manually edit the recognized text
- 📱 **Mobile-Friendly**: Works on mobile devices with supporting browsers
- ♿ **Accessible**: ARIA labels and keyboard navigation support
- 🎨 **Visual Feedback**: Displays recording status, interim results, and user-friendly messages

## Interaction Flow

1. **User clicks "Start Recording"** → Component requests microphone permission
2. **Recording begins** → Blue pulse indicator shows active listening
3. **Interim results appear** → Grayed-out text shows words being recognized
4. **User speaks naturally** → Final text is added to the field
5. **User clicks "Stop Recording"** → Recording stops, final transcript is saved
6. **User can edit or clear** → Manual edits are preserved

---

## Error Handling

The component handles several error scenarios:

- **No microphone permission**: Displays user-friendly error message
- **Browser doesn't support Speech API**: Shows compatibility warning
- **Network error during transcription**: Logs error and shows message
- **Microphone not available**: Gracefully falls back

## Troubleshooting

### "Speech Recognition not supported"
- Use a modern browser (Chrome, Edge, Safari 14.1+)
- Ensure HTTPS is enabled in production

### Microphone not recognized
- Check browser microphone permissions
- Restart browser or system
- Try a different browser

### Poor recognition accuracy
- Speak clearly and at normal pace
- Reduce background noise
- Check if the correct language is selected
- Use a quality microphone

## Best Practices

1. **Always provide a fallback** - Include manual text input option
2. **Clear user feedback** - Show recording status visually and textually
3. **Handle errors gracefully** - Don't block the UI on speech errors
4. **Test in target devices** - Mobile recognition may differ from desktop
5. **Consider context** - Use language prop matching user locale
6. **Privacy notice** - Inform users that microphone access is required
