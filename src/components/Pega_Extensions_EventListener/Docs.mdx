# Overview

The Event Listener widget listens to messages from the Pega messaging service and reacts when a message is received. It supports 2 actions:

- **Display toast**: shows the text of the message in a toast notification.
- **Refresh view**: refreshes the case view where the widget is placed.

**The widget has NO rendering.** It does not display anything on the page, it only listens. Drop it in the **summary view** of the case view. Do **not** place it in an assignment form or in the utilities region.

### Duplicate messages in the summary view

When the case view is collapsed, the summary view can mount the widget more than once, and the messaging service calls every mounted copy once per subscription. Without protection, a single message would show several identical toasts or trigger several refreshes.

The widget removes these duplicates: a message is handled only once, even when several copies of the widget are mounted. Messages are recognized by their message ID (`msgId`), so make sure the publisher keeps the ID generated by the messaging service. Widgets that are configured differently (for example one showing a toast and another refreshing the view) still each handle the same message. Messages without an ID cannot be recognized and are always handled.

## Subscription

The widget subscribes with a `matcher` that must match the matcher used to publish the message. Up to 5 criteria can be set, each one creates a separate subscription with the same matcher. A message is handled when its criteria exactly match one of the subscriptions. A criterion is one of:

- **Current case**: the criteria `ID` with the key of the current case.
- **Current operator**: the criteria `userId` with the operator ID in lowercase.
- **Property**: a criterion name with the value of a property. The subscription follows changes to the value and is skipped while the value is empty.

The selected criteria count controls which criterion settings are shown. For each visible criterion, the name and value settings appear only when its type is **Property**.

## Toast text

With the **Display toast** action, the **Message source** setting selects where the toast text comes from:

- **Field of the received message** (default): the field of the message set in **Message text field** (default `content`). Messages without this field are ignored.
- **Property**: the current value of the property set in **Message text property**, read when the message is received. Nothing is displayed while the value is empty.

Use the **Message source** control in the story above to try both options.
